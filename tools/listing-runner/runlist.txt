# Verified 2026-08-10 on driver 580.178.04 / CUDA 13.3, cuTile 0.3.2. Kernel
# launched and checked against a CPU reference, not merely loaded.
#
# History worth keeping: this used to fail with
#   UndefVarError: `tileiras` not defined in `CUDA_Compiler_jll`
# which looks like a package-version problem but is not. cuTile needs a CUDA 13
# driver (580+). On the old 560.35.03 driver CUDA.jl resolved a CUDA 12 toolkit,
# and that build of CUDA_Compiler_jll ships no tileiras at all. The CUDA 13
# toolchain pulls CUDA_Tile_jll, which supplies it. No cuTile release could have
# fixed it; only the driver upgrade did.
#
# Out of the sweep because cuTile is not in the env-T1 dependency set and is
# experimental enough that adding it risks perturbing resolution for every other
# T1 listing. Run it by hand in a throwaway environment:
#
#   D=$(mktemp -d); LD_LIBRARY_PATH= ~/.juliaup/bin/julia --project=$D -e '
#     using Pkg; Pkg.add("CUDA"); Pkg.add("cuTile"); using CUDA
#     include("src/chapter08/cutile.jl")
#     N=1024; tile=256
#     a=CUDA.rand(Float32,N); b=CUDA.rand(Float32,N); c=CUDA.zeros(Float32,N)
#     @cuda backend=ct blocks=cld(N,tile) vadd_tiles(a,b,c,ct.Constant(tile))
#     CUDA.synchronize(); @assert Array(c) ≈ Array(a).+Array(b)'
#
# Note backend=ct, not backend=cuTile: the listing binds the module as `ct` via
# `import cuTile as ct`, so the bare name cuTile is not in scope. Launching with
# backend=cuTile after only that import fails with UndefVarError.
SKIP:manual-experimental	exec	src/chapter08/cutile.jl
