# CUDA Programming with Julia — Companion Code

Runnable source code, listings, figure-generation scripts, and pinned
environments for the book *CUDA Programming with Julia* (Springer, 2026).

Every numbered listing in the book is extracted from a complete, runnable
program in this repository. The layout mirrors the book's chapter structure, so
any listing can be located, instantiated, and run without retyping code from the
page.

## Repository layout

| Path | Contents |
|:---|:---|
| `src/chapterNN/` | Complete, runnable programs — the source of truth for every listing. |
| `tools/extract.jl` | Regenerates the book's numbered snippets into `listings/` from the `# --- begin:TAG ---` / `# --- end:TAG ---` regions in `src/`. |
| `tools/listing-runner/` | Harness that runs every `src/` program on a GPU host and records PASS / FAIL / TIMEOUT. |
| `figures/scripts/` | Figure-generation scripts with a pinned `Project.toml` + `Manifest.toml` (CairoMakie). |
| `figures/chapterNN/plot-*.jl` | Per-chapter plotting scripts. |
| `Project.toml` | Core ("T1") package environment for the listings. |

The `listings/` directory holding the exact snippets printed in the book is
**not committed** — it is generated from `src/` on demand with `make listings`
(see below), so there is no derived copy to drift out of sync.

## Tested configuration

The listings were compiled and run on real hardware:

| Component | Version |
|:---|:---|
| GPU | NVIDIA GeForce RTX 4070 SUPER (12 GB, Ada Lovelace, compute capability 8.9) |
| NVIDIA driver | Minimum 525.60 (any driver new enough for CUDA.jl 6.10's toolkit artifact) |
| Julia | 1.12.6 |
| CUDA.jl | 6.10 |
| OS | Linux 6.8 (x86_64) |

CUDA.jl downloads a compatible CUDA toolkit automatically as a Julia artifact,
so **no system-wide CUDA installation is required** — only a recent NVIDIA
driver. If a system CUDA is present on `LD_LIBRARY_PATH`, clear it before running
(see *Troubleshooting* below).

## Quick start

```bash
git clone https://github.com/arnislektauers/cuda-julia-book
cd cuda-julia-book

# Instantiate the core environment (installs CUDA.jl and downloads its toolkit).
julia --project=. -e 'using Pkg; Pkg.instantiate()'

# Run any listing's source program in a fresh process, e.g. Chapter 5:
julia --project=. src/chapter05/elementwise_add.jl
```

To reproduce the exact numbered snippets printed in the book into `listings/`:

```bash
make listings      # equivalent to: julia tools/extract.jl --all $(find src -name '*.jl')
```

## Dependency tiers

The core `Project.toml` pins the **T1** set that covers Chapters 1-13's core
material: `CUDA`, `Adapt`, `KernelAbstractions`, `StaticArrays`, `GPUArraysCore`,
`BenchmarkTools`, and the relevant standard libraries.

A handful of Chapter 11-12 case studies pull in a heavier **T2** stack:
`Flux`, `Lux`, `Zygote`, `Enzyme`, `DiffEqGPU`, `OrdinaryDiffEq`, `DataFrames`,
`CSV`, `MLUtils`, `OneHotArrays`, `Optimisers`, `ChainRulesCore`, `CairoMakie`,
`Images`, `TestImages`. Install these on top of the core environment when running
those examples:

```bash
julia --project=. -e 'using Pkg; Pkg.add(["Flux","Lux","Zygote","DiffEqGPU","OrdinaryDiffEq","DataFrames","CairoMakie","Images"])'
```

Chapter 8 examples that use cuDNN or cuTENSOR require the separately registered
`cuDNN.jl` and `cuTENSOR.jl` packages (they are not submodules of `CUDA`).

## Hardware and backend requirements

Most listings run on any recent NVIDIA GPU. Some have additional requirements:

| Requirement | Affected examples | Notes |
|:---|:---|:---|
| **Two or more NVIDIA GPUs** | Chapter 10 multi-GPU: `device_management`, NCCL, MPI, Dagger, and scaling examples | Single-GPU machines cannot exercise multi-device code paths. |
| **Tensor Cores** | Chapter 8 WMMA / mixed-precision matmul | Verified on Ada (CC 8.9); requires Volta (CC 7.0) or newer. |
| **Vendor libraries** | Chapter 8 cuDNN / cuTENSOR examples | Need `cuDNN.jl` / `cuTENSOR.jl` installed. |
| **Non-NVIDIA backends** | Chapter 9 portability: AMDGPU.jl, oneAPI.jl, Metal.jl | Require AMD, Intel, or Apple Silicon GPUs respectively. |

Examples marked **conceptual only** in the text (illustrating an API or pattern
without a runnable driver) load-validate but are not expected to execute
end-to-end.

## Reproducing the tested environment

`Project.toml` pins the packages; the **authoritative `Manifest.toml`** with the
exact tested versions is produced by instantiating on the GPU host. To pin your
own environment identically, commit the `Manifest.toml` generated by
`Pkg.instantiate()` on your machine.

The `tools/listing-runner/` harness automates a full compile-and-run pass:

```bash
bash tools/listing-runner/run.sh T1 360    # core listings, 360 s timeout each
bash tools/listing-runner/run.sh T2 600    # heavy ML/viz listings
```

## Troubleshooting: CUDA libraries from a system path

If a system CUDA toolkit is on `LD_LIBRARY_PATH` (e.g. `/usr/local/cuda/lib64`),
it can shadow CUDA.jl's artifacts and produce errors such as
`symbol lookup error: libcublas.so: undefined symbol`. Clear `LD_LIBRARY_PATH`
before launching Julia, or point CUDA.jl at the system toolkit deliberately with
`CUDA.set_runtime_version!(local_toolkit=true)`. See Appendix A of the book.
